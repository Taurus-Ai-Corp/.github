**Error: Next.js App Router route type violation**
```
Type error: Route "src/app/api/guard/webhook/route.ts" does not match
the required types of a Next.js Route.
 ELIFECYCLE  Command failed with exit code 1.
 ERROR  landing#build: command (/vercel/path0/apps/landing)
        /vercel/.local/share/pnpm/.tools/pnpm/9.15.4/bin/pnpm run build exited (1)
 ERROR  run failed: command  exited (1)
Error: Command "cd ../.. && pnpm turbo run build --filter=landing" exited with 1
```

**Root cause:** `src/app/api/guard/lookup/route.ts` was importing `checkoutSessionCache`
(a `Map` object) directly from `src/app/api/guard/webhook/route.ts`. Next.js 16 App
Router enforces that route files may only export route handlers (`GET`, `POST`, etc.)
and recognised config keys (`dynamic`, `revalidate`, `runtime`, …). Exporting a
non-handler value from a route module causes the build to reject the file.

**Recovery:** The immediately following commit (`f224b85c`) on the same branch moved
the cache to `src/lib/checkout-cache.ts` and imported it from both routes. The next
deployment (`dpl_4s6TcT5DpTCdPg1zEoDafVF1cng3`) reached READY. PR #41 was
subsequently merged to `main` and production deployed successfully
(`dpl_2RCHFhRRFHejnWZqPbroZkeFDLid` — READY).

## Recommended Fix

### For `landing` — prevent recurrence of App Router export violations

1. **Lint rule for route files**: Add an ESLint rule or custom check that flags any
   named export from an `app/**/route.ts` file that isn't a recognised HTTP verb or
   Next.js config key. This catches the pattern before it reaches CI/Vercel.

2. **Shared lib for process-local caches**: Any in-process cache (Map, LRU, etc.)
   shared between route handlers belongs in `src/lib/`, never in a `route.ts` file.
   Consider adding a note to the contributing guide or a `// @route-safe` annotation
   convention for files that may be imported by route modules.

3. **Pre-push type-check**: Run `pnpm turbo run build --filter=landing --dry-run` or
   `tsc --noEmit` locally before pushing feature-branch commits. The error surfaced
   only on Vercel; a local type-check would have caught it immediately.
